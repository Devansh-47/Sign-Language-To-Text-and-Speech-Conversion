Implementation Plan - Sign Language Backend Upgrade
This plan outlines the steps to upgrade the existing Sign-Language-to-Text project into a production-ready FastAPI backend with advanced features like real-time word building, smart suggestions, and evaluation metrics.
User Review Required
IMPORTANT
GPU Dependence: The system requires a CUDA-enabled GPU for TensorFlow. Ensure the environment is correctly configured. Logic Extraction: The existing heuristic logic (hardcoded rules in 
final_pred.py) is critical and will be preserved but refactored into a class structure to be stateless/session-aware.
Proposed Changes
Architecture
The project will be structured under a new app/ directory to keep it clean, while referencing the existing model and dataset.

Component Details
[NEW] app/engine.py
Purpose: Wraps load_model and the complex if-else heuristic rules from 
final_pred.py.
Refactoring: extracting the landmark drawing and rule checking into a SignPredictor class.
Inputs: Landmark list or Image frame.
Outputs: Top-N probabilities, Heuristic-adjusted character.
[NEW] app/session.py
Purpose: Manages user state.
Features:
Session class storing current_word, sentence, committed_frames, etc.
In-memory storage (dictionary of sessions).
[NEW] app/suggestions.py
Purpose: Logic for word suggestions.
Features:
enchant dictionary integration (as used in original) or a loaded word list.
Scoring formula: Score = 0.4*P_gesture + 0.4*P_language + 0.2*P_personal.
[NEW] app/smoothing.py
Purpose: Moving average and stable commit detection.
Logic: 10-frame buffer, exponential decay.
[NEW] app/main.py
Endpoints:
POST /v1/frame: Receives image -> Detects Hand -> Predicts -> Updates Session -> Returns JSON.
POST /v1/commit: Forces commit of current state.
GET /v1/session/{id}: Returns state.
[NEW] app/evaluation/benchmark.py
Purpose: Runs evaluation against a dataset (e.g. AtoZ_3.1) or synthetic tests.
Outputs: out/report.json.
Verification Plan
Automated Tests
I will create a script verify_api.py to simulate a client:
Startup: Check /v1/health returns 200 and model loaded status.
Prediction: Send a dummy image (black/white) to /v1/frame and verify JSON response structure.
Session flow: Send multiple frames, check if partial_word updates.
TTS: Call /v1/tts with text and check if audio bytes/success is returned.
